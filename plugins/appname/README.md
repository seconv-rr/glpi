# Application Name

Renames the product from **GLPI** to **SECONV-RR**, and nothing else.

## Why a plugin is needed

`$CFG_GLPI['app_name']` is assigned literally in `src/autoload/CFG_GLPI.php:47`. It is not a row
in `glpi_configs`, so no administration screen writes it — only code that runs before the page is
rendered can change it. `plugin_appname_boot()` is that code: the kernel fires plugin boot at
priority 140, ahead of `SessionStart` (130) and of every controller
(`src/Glpi/Kernel/ListenersPriority.php:64`), and it runs on anonymous pages as well, which is
what the login page needs.

Three places read the value:

| Reader | What it shows |
| --- | --- |
| `templates/layout/parts/head.html.twig:50` | Browser tab title |
| `src/NotificationTemplate.php:291` | "Automatically generated by %s" footer of notification e-mails |
| `src/Glpi/Security/TOTPManager.php:135` | Issuer label an MFA app puts next to the account |

## What it does not do

The logos and the favicon are files under `public/pics`; they never go through `app_name`. In
production they are baked into the image (`deploy/coolify/Dockerfile`), locally they are written
by `branding/seconv-rr/apply.sh`. The login-page background is GLPI's own.

## Why not the UI Branding plugin

[i-Vertix/glpi-modifications](https://github.com/i-Vertix/glpi-modifications) (`mod`) does the
same rename through a settings screen, but its activation hook is not a no-op
(`plugin_mod_activate()` in its `hook.php`):

- it copies *its own* sample images — the i-Vertix logos — over `public/pics`, destroying the
  SECONV-RR files the image ships;
- it sets `login="1"`, which replaces the login-page background with the i-Vertix photo;
- it renames the instance to "i-Vertix" whenever the current name is still the GLPI default.

Every one of those runs again on each activation, and its image directory lives in the `/var/glpi`
volume, so a redeploy does not clear it. Forty lines of our own are cheaper than fighting it.

## Install

```bash
php bin/console plugin:install --username=glpi appname
php bin/console plugin:activate appname
```

## Changing the name

Edit `PLUGIN_APPNAME_APP_NAME` in `setup.php`. Any string works; it is never parsed.
`deploy/coolify/smoke.sh` reads the constant from here, so nothing else has to be updated.

## When this stops working

Silently, in two ways. GLPI moves one of the three things the plugin stands on — the
`$CFG_GLPI['app_name']` default, the `plugin_<key>_boot()` call in `src/Plugin.php`, or the
`config('app_name')` in `templates/layout/parts/head.html.twig` — and the plugin keeps loading
while the tab title goes back to "GLPI". Or GLPI moves past the `max` this plugin declares,
refuses to activate it, and the same thing happens on the next redeploy.

`deploy/coolify/verify-branding.sh` checks all four and fails the production build. It cannot
tell whether the plugin is *active* in a given instance, which is database state — for that,
`deploy/coolify/smoke.sh <url>` reads the login page's title.
